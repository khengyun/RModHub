# Synthetic nanopore sample data (signal branch)

**Everything in this directory is synthetic.** No RNA was sequenced: the reference
transcripts are random ACGT strings with a 20-nt poly(A) tail, and the signal is drawn from a
simple k-mer level model. The files exist so that the DirectRM pipeline can be exercised
end to end (`POST /api/jobs/signal/sample`) without a multi-GB download. Do not use them to
draw biological conclusions.

Generated by `scripts/make_signal_sample.py` version 1.0.0:

```
uv run --with "pod5==0.3.35" --with "lib-pod5==0.3.35" \
    python scripts/make_signal_sample.py --out app/samples/signal --seed 20250831 --layout rna_raw \
    --levels worker/directrm_vendor/9mer_levels_v1.txt
```

| setting | value |
|---|---|
| seed | `20250831` (`numpy.random.default_rng`) |
| layout | `rna_raw` |
| k-mer level table | ONT `kmer_models` RNA004 `9mer_levels_v1.txt`, sha256 `1d366c9e060f31be1d6489b88b415666fba42f1c4006e1e549666f4a50f13e63` |
| generated with | Python 3.12.13, numpy 2.5.2, pod5 0.3.35, pysam 0.24.0 |
| pod5 format | written with pod5 <= 0.3.45 (POD5 v5), which every pod5 reader opens, including the 0.3.35 pinned in `tools/Dockerfile.subset`; the worker (lib-pod5 0.3.47) reads v5 and the v6 that pod5 0.3.46+ writes |
| kit emulated | RNA004 (`sqk-rna004`, `FLO-MIN004RA`, 4000 Hz, model stride 5) |
| reads | 88 (mean 16085 samples, ~30 samples/base) |

| file | content |

| `MANIFEST.json` | bytes + sha256 of every file, the pod5 content digest and the generator arguments |

## Validation against upstream

The unmodified upstream DirectRM scripts (`sampling.py`, `feature_extraction.py`; Python 3.9, ont-remora 3.2.0, pod5 0.3.35, pysam 0.24.0, numpy 2.0.2) were run on this exact data set: `sampling.py` (`--min_coverage 30 --max_coverage 150`) selects 76 read ids (tx_A + tx_B; tx_C dropped), `feature_extraction.py` (`--kmer 9 --step 5`) reports `0 failed` and writes `seq` with shape (N, 9, 4), N = **3648** k-mers (all dwell columns have non-zero standard deviation, so the later z-scoring stages cannot crash on this input). Measured orientation numbers on this data set: Pearson(per-base signal mean, expected 9-mer level) = 0.994 with Remora's RNA convention (`reverse_signal=True`), 0.014 without it, and 0.749 through the unmodified DirectRM path (no `reverse_signal`, after its banded refinement).

## Signal model and move-table orientation

Per base, dwell is a whole number of stride blocks (lognormal, mean ~6 blocks x 5 samples),
`pA = 80 + 15 x level + N(0, 2.5)` with `level` taken from the 9-mer table at the
dominant position (3), preceded by a leader of `ts ~ U(200, 800)` samples. The
BAM satisfies the invariants Remora checks: `len(mv) - 1 == (ns - ts) // stride` and
`sum(moves) == len(query incl. soft clips)`.

Layout: `rna_raw` (default) - the real dorado convention for direct RNA: raw signal in sequencing time order (3' -> 5' of the read), BAM `seq`/`qual` reversed to 5' -> 3', `mv` table in raw-signal order (move *i* <-> base *L-1-i*), `ts`/`ns` in raw coordinates.

Orientation caveat: DirectRM's `feature_extraction.py` calls
`remora.io.Read.from_pod5_and_alignment(...)` without `reverse_signal=True`, i.e. it pairs
move *i* with base *i*. On real dorado RNA output (and therefore on the default `rna_raw`
layout) the per-base signal is thus mirrored within each read relative to Remora's own RNA
convention; the data set reproduces that upstream behaviour faithfully instead of hiding it.
The `--layout dna_like` option exists only as a diagnostic to see the pipeline on
self-consistent orientation.

## Determinism

Two runs with the same arguments produce byte-identical BAM, BAI, FASTA, FAI, CSV and
README. The pod5 container embeds a random file identifier, so its file hash differs between
runs; `MANIFEST.json` therefore also records a **content digest**
(sha256 over reads sorted by read_id string: for each read, read_id (36 ASCII chars) + b'\n' + signal as little-endian int16 bytes + b'\n') which is identical across runs.
